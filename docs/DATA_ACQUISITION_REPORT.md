در این اجرا جست‌وجوی وب برای منابع سازندگان انجام شد؛ پنج دیتاشیت رسمی از endpoint رسمی ناشر با ابزار بازیابی صفحه باز و بخش‌های مرتبط به‌صورت متن استخراج‌شده بررسی شد. برای هر قطعه فقط ادعاهایی که در بخش/جدول رسمی قابل مشاهده بود در seed قرار گرفت. فایل PDF خام در مخزن محلی ذخیره نشده است؛ URL رسمی، نسخه، تاریخ دسترسی و بخش سند در SQLite ثبت شده‌اند. این یک بررسی دستی محدود از متن استخراج‌شده است، نه ممیزی کامل همه صفحات PDF، تضمین اصالت قطعه فیزیکی یا آزمایش روی برد.

سه رکورد `failure_modes` صرفاً شرایط خارج از Operating Conditions سه مبدل/درایور (TPS5430، LM2596 و DRV8825) هستند؛ آن‌ها آمار خرابی میدانی یا تشخیص قطعی نیستند. سه `component_diagnostic_profiles` نیز فقط نقطه/نام سیگنال و بازه کاریِ منبع‌دار را به موتور می‌رسانند؛ تطبیق بیرون بازه فقط یک شرط قابل بررسی است و سلامت یا خرابی قطعه را تعیین نمی‌کند. پنج قاعده اولیه عمدتاً triage محافظه‌کارانه‌اند و همگی `needs_review` باقی مانده‌اند.

**اطلاعات عمداً نامشخص:** 2 رکورد قطعه (1N4148 و IRLZ44N) محدوده کار توصیه‌شده یا نقشه پایه‌های کامل در بانک ندارند؛ فیلدها به‌جای حدس خالی مانده‌اند و یادداشت محدودیت دارند. بنابراین «5 قطعه دارای منبع رسمی» به معنی تکمیل همه فیلدهای الزامی نیست. تعداد رکوردهای قطعه با وضعیت کلی `needs_review/conflicting` فعلاً 0 است، اما دو رکورد فوق فیلدهای ناشناخته دارند.

## تعارض‌ها و محدودیت‌ها

- برای هر قطعه در مجموعه اولیه فقط یک دیتاشیت مرجع ثبت شده است؛ تطبیق مستقل دو دیتاشیت برای تمام مقادیر انجام نشده، بنابراین `verified_multiple_sources` ثبت نشده است.
- دیتاشیت Nexperia قدیمی است؛ صفحه محصول Nexperia درباره انتقال تولید/پشتیبانی شیشه‌دیودها به Tak Cheong اطلاع می‌دهد. سازنده/اصالت نمونه فیزیکی باید مستقل کنترل شود.
- دیتاشیت IRLZ44N بررسی‌شده legacy است؛ مقدار جریان/توان تحت شرط case temperature و گیت مشخص آمده است و نباید به‌عنوان ظرفیت قابل اتکای یک برد فرض شود.
- هیچ رکوردی روی میزکار/برد واقعی آزمایش نشده است؛ درصد دقت سیستم گزارش نمی‌شود.
- قوانین بازنشده برای هر برد ناشناس فقط سؤال/تست عمومی و مشروط پیشنهاد می‌کنند؛ نقطه، حد و پایه باید از شماتیک یا دیتاشیت همان برد بیاید.

## ابزار intake و اجرای مجدد

ابزار `tools/source_intake.py` ورودی JSON صریح کاربر را ممیزی می‌کند، قطعات تکراری/فیلدهای ناقص و دامنه URL را کنترل می‌کند، و می‌تواند با `--download` فقط PDFهای HTTPS از ناشران allowlist شده را دانلود کند. `--extract-text` اختیاری است و به `pypdf` نیاز دارد؛ استخراج متن هرگز مقادیر را به‌صورت خودکار تأیید نمی‌کند. واردکردن به SQLite فقط با `--import-approved` و فیلدهای صریح `human_approved=true`، بازبین، بخش‌های بررسی‌شده و یادداشت دستی مجاز است؛ رکورد تکراری بازنویسی نمی‌شود.

```bash
# ممیزی manifest بدون اینترنت و بدون تغییر DB
python tools/source_intake.py data/sources/manifest.example.json \
  --out data/reports/source_intake_report.json

# دانلود فقط با درخواست صریح؛ پیش از اجرا مجوز/شرایط ناشر را بررسی کنید
python tools/source_intake.py my_parts.json --download --pdf-dir data/datasheets

# واردکردن فقط پس از بازبینی انسانی مستند
python tools/source_intake.py reviewed_parts.json --import-approved \
  --db "$HOME/.local/share/circuit-ai/circuit_ai.sqlite3"

# گزارش کیفیت/تعداد پایگاه
python tools/manage_data.py report
```

ابزار local سرچ اینترنتی را خودکار نمی‌کند؛ URLهای رسمی باید به manifest افزوده شوند. این محدودیت عمدی است تا crawl، دورزدن محدودیت سایت، دانلود ناخواسته یا تأیید خودکار اطلاعات رخ ندهد.

## پایگاه، خروجی و بازیابی

- مسیر اجرایی پیش‌فرض: `~/.local/share/circuit-ai/circuit_ai.sqlite3` (یا `$XDG_DATA_HOME/circuit-ai/circuit_ai.sqlite3`).
- در مخزن کد، `data/catalog.sqlite3` فقط تصویر اولیه قابل ممیزی از کاتالوگ است؛ برنامه نصب‌شده از مسیر کاربری خود استفاده می‌کند و پرونده‌های مشتری را وارد مخزن نمی‌کند.
- ساخت پشتیبان: `python tools/manage_data.py backup ~/Documents/circuit-ai-backup.sqlite3`
- بازیابی اعتبارسنجی‌شده: `python tools/manage_data.py restore ~/Documents/circuit-ai-backup.sqlite3`؛ پایگاه فعلی، اگر وجود داشته باشد، با پسوند `.before-restore-<time>.bak` حفظ می‌شود.
- خروجی JSON: `python tools/manage_data.py export ~/Documents/circuit-ai-export.json`؛ فایل خروجی ممکن است حاوی اطلاعات محرمانه تعمیر باشد.
